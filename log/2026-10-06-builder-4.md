## Done

- **Relation measures** (`src/core/relations/`): every `rel` of SPEC section 7, measured on the footprints at height 0. `prepareRelations` resolves targets once and returns, per relation, a measure (violation and message) or the reason it is skipped, so the solver measures candidate layouts without building scenes. Screen x is `u cos(angleU) + v cos(angleV)`; depth is along the camera direction. Distance to a lane uses the lane rectangle of 9.1; `on_lane` follows any polyline. `facing`, targets of the wrong kind, unsupported lane shapes, unbounded strip edges, zones without points and missing parameters (`aligned` without `axis`, `order_along` with fewer than 2 objects) give `skip`. Status `satisfied` up to 1e-6; the soft penalty sums `weight * violation` over soft relations that are not skipped.
- **`isoblock relations`** with a text report (summary line, `OK|BAD|SKIP <id> <rel>: <message>`) and `--json` (`{ scene, results }`); exit 0 when every hard relation is satisfied, else 1.
- **Solver** (`src/core/solver/`): movable objects (all, or `--only`) without a `pos` lock; `pos.u`, `pos.v` and pointer locks on a position fix that coordinate. The objective is lexicographic: hard violations plus broken constraints (corners outside the view region, new overlaps of moved footprints), then the soft penalty, then the distance moved. The search is deterministic: per object, the best of 8 directions times 8 step lengths (6.4 down to 0.05) plus the way back to the start; then the same moves for groups (the movable objects of one relation, and connected sets of up to 12); then up to 40 seeded perturbations of the objects in broken relations. Every changed coordinate is snapped to the 0.05 grid and rounded to 6 decimals; unchanged coordinates keep their exact value. The score is updated per move (cached relation values, per-object overlap sums), with a fast path for one moved object.
- **Minimal conflict set**: deletion filtering in file order over the hard relations that are not skipped; each test is a solution search for the remaining set (25 perturbations). A layout that solved one test is reused for later, smaller sets.
- **`isoblock solve`** with `--only`, `-o` (proposal in the saved format, assumptions follow their paths), `--patch` (`# solve proposal` and one `move` per moved object, offsets in plain decimals), `--json` (keys in the order of SPEC section 8). The input file is never written: an output naming it is `E_USAGE`. Exit 0 when solved and every check of the proposal passes, else 1.
- A `solve` line in a patch stays `E_USAGE`; the message now says to run `isoblock solve <scene> --patch <file>` and apply the patch it writes.
- `docs/AGENT_GUIDE.md`: relation reference, `relations`, `solve`, the workflow `relate` -> `solve --patch` -> `patch`; every example was run with the built tool on `yard`. `CHANGELOG.md` updated under `Unreleased`. All stage 4 tasks in `ROADMAP.md` are ticked.

Not touched: `SPEC.md`, `AGENTS.md`, `MAINTAINING.md`, `tests/golden/`, `tests/fixtures/`, `package.json`, `schema/`. The scene file format did not change and no fixture needed a change. No new dependency. `followAssumptions` in `src/core/patch/apply.ts` is now exported for the proposal.
