# 2026-10-19 · maintainer · session 18

Opens stage 9, from branch `maintainer/stage-9`.

## Why

Users of release 0.8.0 reported, in words that do not depend on their project:

1. `render -o out.png` stops with `E_INTERNAL: unreachable` (exit 70) on some scenes whose SVG renders.
2. `in_region` tests footprints at h = 0, so an object high above the ground can be off screen while its footprint is inside the region.
3. No check keeps two lanes apart, or a lane off an area.
4. `min_screen_size` measures the whole drawn box, footprint depth included; "how tall a character looks on screen" needs the vertical extent only.
5. The solver reported a conflict for hard relations that a layout meets (objects started inside a lane that had moved).
6. `export --target runtime` drops `x-` keys.
7. Zones and lanes have no height; states cannot hide a part of an object or a frame region; there is no camera elevation parameter.

The owner also asked that builder sessions from this stage on can run in any coding agent, with every repository rule kept.

## Done

- **Item 1, cause.** resvg 2.6.2 stops when a polygon carries the group attribute `opacity` and shapes reach far outside the frame: the WebAssembly build with `unreachable`, the native build with a panic in its geometry code (`geom.rs`, an `unwrap` on `None`); both stop on `openstrip`. On 80 random scenes of two large quadrilaterals and one semi-transparent region, each rasterized in a fresh process: 66 crashes with `opacity`, 0 with the shapes clipped to the frame grown by 4 px, 0 with `fill-opacity` and `stroke-opacity`. On 30 scenes of very large dashed semi-transparent shapes: 30 crashes with `opacity`, 0 of 60 with `fill-opacity` and `stroke-opacity`. A panic also leaves the WebAssembly instance unusable for later calls in the same process.
- **Item 1, fix chosen:** `fill-opacity` and `stroke-opacity` instead of `opacity` (SPEC 14). It changes no geometry; the image changes only where a semi-transparent stroke covers its own fill. Clipping was rejected: it changes pixels inside the frame (the dash pattern restarts at a new first vertex and long edges are rasterized differently), so implementations would have to agree on the clipped vertex order to the pixel.
- **Items 2 to 4:** SPEC 9.4 (`in_region` with `measure: "drawn"` and `maxOutside`, `min_screen_size` with `measure: "height"`, the check `lane_apart`), the catalog of section 9, the labels and cells of 11.1.
- **Item 5:** not a contract violation: SPEC 8 lets `conflict` mean "no layout found", and section 18 already names the limit. Section 8 now says so where the outcome is defined, with the remedy; the builder writes it into the agent guide.
- **Item 6:** by design: SPEC 13.7 copies entries without their `x-` keys. Recorded with item 7 as asked for and not scheduled (section 17).
- **Fixtures:** `tests/fixtures/measures/` (synthetic scene `measures`, round numbers chosen for the tests: a tall object whose top leaves the view, a raised plate on a post, a flat mat, two lanes 0.3 apart, a crossing lane, a diagonal lane, a concave zone whose bounding box overlaps a lane while the zone does not, a touching zone, an overlapping zone with its points in clockwise order, a zone without points; results in the default state and in state `no_tower`). Export case `openstrip`: one box, a strip with an open bound and a semi-transparent region, round numbers found by a search over round frames, scales and regions for a scene on which release 0.8.0 stops. Block images `export/yard.png`, `export/garden.png`, `export/openstrip.png`, `states/yard.closed.png` drawn with `fill-opacity` and `stroke-opacity`.
- **Any coding agent:** `AGENTS.md` names what the environment needs and what to do without Chromium or Godot, requires a no-reply git identity, removes environment-added traces, and puts the pull request text in the log; SPEC 20 states the rules for every tool and separates what builders and the maintainer may write on GitHub; `MAINTAINING.md` has a tool-neutral prompt and review steps 16 and 17.
- **Publication check:** `scripts/check-publish.mjs` (`npm run check:publish`), its tests in `tests/repo/checkPublish.test.ts`, and the workflow `.github/workflows/publish-rules.yml`. The workflow uses `pull_request_target`, so the workflow file and the script are those of the base branch and a pull request cannot loosen them; it reads the pull request's commits with git, runs none of its code, has read-only permissions and no secrets, and passes the title, description and branch name to the shell only through environment variables.
- **Independent review** of this branch before the first push, by a separate agent session that had not seen the work. Fixed from it: the end-of-session order (process items moved from the checklist to the done-when line); who rewrites pushed commits; owned paths in SPEC 20; the trailer rule; the `Agent:` line; branch names; `threshold`, `ids` order, `outside` order, `overlap` on `skip` and the shoelace sign in 9.4, and a clockwise zone in the fixture; in the script: the base branch's copy in the workflow, `+++` lines inside hunks, `diff.noprefix`, session links and addresses in commit messages, a second `Co-Authored-By` line anywhere, version strings and SSH remotes taken for addresses, the no-reply test, Codex and Amp links, exit 2 on git errors; and the numbers of `openstrip`, which are now round.
