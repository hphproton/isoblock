## The fixes

- A turned footprint is scored against the input scene: the solver model keeps the input footprints beside the turned start, an object counts as moved when its footprint differs from the input one, the overlaps that already count are those of the input, and distance runs between footprint centers. - A coordinate that a turn changes is snapped to the 0.05 grid as the search snaps; one it does not change keeps its value. The patch writes `rot` and then a `move` from the position `rot` gives whenever the proposal differs from it.
- With `--rotate` the minimal conflict set is deletion filtering with the solver that turns; a layout found for one trial is tried on the next before a new search.
- The `facing` mark of the Relations overlay has a filled head at its tip; `overlay("relations")` is unchanged.

The builder's tests cover the three scenes of the review and a turn whose snap lands back on the input position.
